# Blood II server-class catalog for save/load design

Read-only research, 2026-10-20. Original source: `lithtech/Blood2` in the LithTech reference tree
(paths below are relative to `ObjectDLL/` unless prefixed). OpenBlood2:
commit `8c1ad35b` (paths relative to `src/game/` unless prefixed).
Tables were generated by parsing every non-commented `END_CLASS_DEFAULT*` line, the C++
`class X : public Y` declarations, `X::Save/Load` definitions and `MID_SAVEOBJECT` handlers;
member lists are parsed from headers (non-static data members), so "unsaved members" are
**approximate** (name not referenced in the Save body). World usage was measured by running the
existing `blood2 --inspect-world` diagnostic (a local dev build) on all 58 mounted
retail worlds; numbers are `worlds/instances` from the DAT object lists (data, not code version).

## 0.1 Original save/restore mechanics that shape the catalog

1. **Only `USRFLG_SAVEABLE` objects are saved.** `CBloodServerShell::SaveGame` walks active and
   inactive objects and adds those with `USRFLG_SAVEABLE` (players only when `bSavePlayers`) to the
   list given to `ServerDE::SaveObjects` (BloodServerShell.cpp:1004-1061; flag at
   `Shared/ClientServerShared.h:18`). Console and portal state are saved via
   `SAVEOBJECTS_SAVEGAMECONSOLE|SAVEOBJECTS_SAVEPORTALS`.
2. **Restore does not reload world objects.** `LoadWorld` omits `LOADWORLD_LOADWORLDOBJECTS` when
   restoring (BloodServerShell.cpp:940-944), then `RestoreObjects(path, 0, RESTOREOBJECTS_RESTORETIME)`
   (:1090). Only `CF_ALWAYSLOAD` classes are rebuilt from the DAT — "always loaded from the level file
   and can't be saved to a save game" (`AppHeaders/serverobj_de.h:62-63`).
3. **Setters of USRFLG_SAVEABLE** (subclasses inherit): Tchernotronic.cpp:205, PickupObject.cpp:352,
   CameraObj.cpp:332, ClientLightFX.cpp:554 (**only if initially ON**), Rain.cpp:218,
   VolumeBrush.cpp:408/870, CinematicTrigger.cpp:295, ClientWarpGateSFX.cpp:306, DetailSprite.cpp:205,
   KeyFramer.cpp:536, ClientLightningSFX.cpp:129, ClientExplosionSFX.cpp:338, DestructableBrush.cpp:236,
   TripLaser.cpp:299, ClientLaserBeamSFX.cpp:121, corpse.cpp:277, Spawner.cpp:108, Trigger.cpp:513,
   SoundFX.cpp:332, SeeingEye.cpp:379, BaseCharacter.cpp:88 (all characters incl. player),
   Door.cpp:470, Projectile.cpp:314, DestructableModel.cpp:450, ClientParticleStreamSFX.cpp:130.
   Trigger.cpp:38 clears all user flags before a trigger-removal ("Quick hack to fix airship door
   load/saves").
4. **Original latent losses (by code reading):** `RandomSoundFX` has Save/Load
   (RandomSoundFX.cpp:452/490) but never sets SAVEABLE and is not ALWAYSLOAD → it vanishes after a
   restore (20 worlds/54 instances). World-placed `CGib` (7/76), `FlagStand`/`FlagObject` (MP), and
   any `ClientLightFX` family light that starts OFF (HandleTrigger toggles only USRFLG_VISIBLE,
   ClientLightFX.cpp:327-356) are likewise lost. `NagaCeilingDebris` is registered with parent
   CDestructableBrush but its C++ base is `B2BaseClass` (NagaCeilingDebris.h:7) → no Save, not saveable.
   ALWAYSLOAD objects (Key, PathPoint, SparksObj, ParticleSystem, PolyGrid, ExitHint, SmellHint,
   CameraSpot, WorldProperties, GameStartPoint, Script, WreckingBall, SoccerGoal, LightFX, engine
   Model/Sprite/Sound/Container/sky objects) come back in their authored state: e.g. SparksObj ON/OFF,
   ParticleSystem toggles and runtime smell-trail SmellHints are not preserved; Keys reappear while
   the saved KeyFramer has `m_bFirstUpdate=false` (KeyFramer.cpp:725/791), so they are probably not
   re-consumed.
5. **Engine-level object state is saved by the engine**, not by game code — including the
   special-effect message ("all the data in the special fx message is saved/loaded for us",
   ClientLightFX.cpp:637-638, ClientParticleStreamSFX.cpp:266-267). The 1.x engine layout is not in
   this tree; OpenBlood2 must define its own generic record (transform, flags, user flags, dims,
   model/anim, SFX payload, next-update/deactivation, velocity/accel, attachments).
6. **Dispatch order:** subclasses handle `MID_SAVEOBJECT` first, then call the base
   `EngineMessageFn` (e.g. CultistAI.cpp:124-136); `bc_EngineMessageFn` forwards to aggregates.
   AI_Mgr re-inserts itself into its faction list on load (`InsertMe`, AI_Mgr.cpp:745); TheHandAI,
   Thief and BoneLeech re-run base Load then fix attachments (TheHandAI.cpp:124-140,
   thief.cpp:122-130, boneleech.cpp:133-140).
7. **Object references** must use `WriteToLoadSaveMessageObject`/`ReadFromLoadSaveMessageObject`
   (`AppHeaders/CSBase.h:49-71`). Only these are written: AI_Mgr m_hTarget/m_hTrackObject/m_hEnemyAttach
   (AI_Mgr.cpp:6766/6768/6821), CameraObj m_hLinkObject (:628), CDestructable/CDebris/Rotating/CMovement
   m_hObject (owner self-ref), Door m_hTriggerObj (:1115), CInvTheEye m_hSeeingObject
   (GameInvItems.cpp:939), SeeingEye m_hOwner/m_hStuckObject (:492-493). Notably CProjectile does not
   save `m_hFiredFrom`, CCorpse/Fanatic do not save attachments, VolumeBrush re-creates its PolyGrid
   surface on Load instead (VolumeBrush.cpp:765 commented, :861-866).
8. **KeepAlive (NEW_LEVEL):** `KeepAliveSave` saves only player objects to `Keep.sav` with
   `dwSaveFlags=1`; `KeepAliveLoad` restores them with load flag 1 (BloodServerShell.cpp:1142-1208).
   Each class Save receives this flag (e.g. CInventoryMgr distinguishes save types).
9. **Client blob:** the client sends `SaveClientData` (night goggles, wonky/blind/fade state, music
   level, last load type, game type, objectives title/text — ClientShellDLL/BloodClientShell.cpp:6351,
   restored by `LoadClientData` :6391 on SMSG load at :5152) inside `CMSG_SAVEGAME`; the server stores it on CPlayerObj
   (`SetClientSaveData`, PlayerObj.cpp:5905) and CPlayerObj::Save writes it (PlayerObj.cpp:6675-6679).

## 1. Original ObjectDLL class catalog

Columns: *Flags/build* = class flags (`HIDDEN`, `ALWAYSLOAD`) and preprocessor guard; *Save/Load* =
own definition `file:line / Load line`, or the ancestor whose Save runs; *Added unsaved members* =
for (b)/(c)/(d) the non-static members declared between the class and its saving ancestor; for (a)
the class's own members whose name does not appear in its Save body (approximate; noise members such
as `m_pServerDE`, `m_Link`, `AIShared` filtered). *OpenBlood2*: `reg` = registered;
`agg†` = the CDestructable/CInventoryMgr typed snapshot APIs exist (`original/DestructableSave.cpp:61/103`,
`original/InventorySave.cpp:66/108`) but are wired only to player KeepAlive/exit capture;
`SG‡` = AI_Mgr savegame guards retained (`original/AIRuntime.cpp:374` PRECREATE_SAVEGAME,
`:579` INITIALUPDATE_SAVEGAME) with no Load behind them.

## 5. Method notes and caveats

- Category (c)/(a) "unsaved" member lists come from name matching against Save bodies; members
  written through helper calls or local copies may be listed falsely (e.g. CPlayerObj, CInventoryMgr).
  Treat as a review checklist, not a verdict.
- Engine-level object state saved by LithTech 1.x is not in this source tree; §0.1-5 lists what game
  code assumes it covers.
- World counts come from the pre-existing local dev build (610ead8) `--inspect-world`; class names
  and counts are DAT data, but its "Class not ported" labels are stale (those classes are now
  registered). The inspection logs are local research output and are not committed.
- Original Save quirks worth preserving or deliberately fixing: Naga type/object-ref mismatch;
  RandomSoundFX never saveable; initially-OFF ClientLightFX not saveable; CBaseCharacter Save empty;
  ClientParticleStreamSFX saves only `bOn`; VolumeBrush rebuilds its PolyGrid surface on Load;
  AI_Mgr re-inserts into faction lists on Load; BoneLeech/Thief/TheHand re-attach to `g_pPlayerObj`.

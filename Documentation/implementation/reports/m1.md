# M1 — Original-Code Boundary and Object Lifetime

**Completed for the selected boundary on Linux, 15 October 2026.** [Blood2](../../../README.md) now links actual original `B2BaseClass`, `CameraSpot` and `Key` code through a typed adapter. The original `BaseClass` and aggregate dispatch code is shared with the engine. This closes the bounded M1 contract gate; it does not mean that a level, player, weapon, AI or local game session works. **M2 is next.**

Before implementation, the workspace root Git repository was created and only `AGENTS.md` and `README.md` were committed as **`139d14c`** (`docs: track workspace guidance and overview`). `Blood2/` remains an independent repository, with implementation changes in its working tree. The root ignore file excludes the seven nested repositories instead of turning them into accidental submodules. No remote was added.

## Delivered Implementation

- Three project targets: `engine`, `blood2_game`, and `blood2_app`. Original code is copied into the new project; no prototype or reference checkout is a build dependency.
- A normally constructed `ServerAdapter`, typed callback members and actual virtual message dispatch. One authoritative adapted header set; no fabricated vtables, generic cast stubs, duplicate-symbol linker flags or EnTT.
- Original objects and inherited properties; explicit world/runtime/string/restore reasons; nested property contexts; precreate mutations applied before initial update.
- Stable handle tokens and generation-checked internal IDs; scheduled updates; inactive objects; deferred removal; safe nested creation and removal from cleanup callbacks.
- Named-object snapshots, object links and link-break notifications; owned strings and bounded object-message buffers with tested lifetimes.
- Inspector creation/removal controls and live object identity, properties, transforms, flags, lifecycle, schedules and `Key` fields. UI mutations are applied at the next simulation boundary; selection invalidates after destruction.
- A headless executable, `object_contract_tests`, exercising original objects plus synthetic edge cases without initializing SDL or using retail assets.

The detailed [service and ownership contract](../../contracts/object_contracts.md) distinguishes implemented APIs, explicit errors, limits and unverified compatibility. The [provenance ledger](../provenance.md) records the original donor and adaptations. The [source snapshot](evidence/m1.json) and [original-source adaptation patch](evidence/m1-original-adaptations.patch) make this result reproducible and reviewable.

### Audit Regression Coverage

| Requirement | Assertions in the new runtime |
| --- | --- |
| **A01 — Deferred destruction** | Self-removal continues safely inside its callback; removal of another scheduled object skips its update; duplicate removal is harmless; destruction happens at frame end; cleanup callbacks can remove a third object |
| **A02 — Update semantics** | A 0.01-second rearm survives a callback returning 1; zero disables; inactive objects do not update; newly spawned objects wait for a later step; invalid deltas fail |
| **A03 — Creation order/context** | Precreate changes type, transform, filename, name and flags before storage; nested string spawn restores the outer property context; all four reasons reach callbacks; inherited defaults and strict runtime-property strings work |
| **A04 — Aggregate forwarding** | A real `CameraSpot` subclass calls the original parent path; the original `bc_*` functions forward each engine/object message once to a test aggregate, with no recursive object redispatch |
| **A05 — Typed interface** | Calls through real `CSBase*`/`ServerDE*` virtual methods and typed callbacks reach the implementation; no manually reconstructed ABI |
| **A07 foundation / A17** | Named lists and directed links work; stale handles and recycled slots cannot resolve to a new instance; editor selection clears; bounded messages and strings are released; unsupported movement/save/restore report failure |
| **Rejected/recursive creation** | Refused precreate never receives initial update; precreate removal does not revive the object; invalid state is rejected; recursive spawning stops at 64 contexts and restores all contexts on unwind |

Original-code observations are tested directly: `CameraSpot` disables its update during initialization; `B2BaseClass` removes world objects excluded by the selected difficulty; `Key` reads its world properties and frees its strings through the adapter. The aggregate used for dispatch-count assertions is a **synthetic test aggregate** executing through original base/forwarding code; original gameplay aggregates such as `Rotating` are not yet imported.

## Reproduce

From `Blood2/`, the existing ignored local presets use the supplied installation:

```sh
cmake --preset local-debug
cmake --build --preset debug -j 8
ctest --preset debug
cmake --preset local-release
cmake --build --preset release -j 8
ctest --preset release
./build/debug/blood2
```

Use the public `debug`/`release` presets elsewhere; GPU/private tests are opt-in. To run only object contracts without a display or game data:

```sh
ctest --preset debug -L objects
./build/debug/tests/object_contract_tests original_objects
```

Clang sanitizer reproduction, with the inspector and GPU tests disabled:

```sh
cmake -S . -B build/sanitize -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ \
  -DBLOOD2_INSPECTOR=OFF -DBLOOD2_SANITIZERS=ON -DBLOOD2_GPU_TESTS=OFF
cmake --build build/sanitize -j 6
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1 \
  ctest --test-dir build/sanitize -L headless --output-on-failure
```

The imported sources, adapter, engine code and test executable are instrumented. SDL dependencies are built normally; no claim is made about sanitizer coverage of the GPU driver or a rendered sanitizer run.

## Limits and M2 Handoff

The source interface deliberately exposes only the M1 service subset. Class registration is not a claim of broad game coverage. No original client/server shell, archive reader, world loader, rendering of game objects, collision, animation, audio, attachment, save-file restoration or playable behavior is implemented. Retail resources remain external; their metadata is checked, and their contents are still unparsed.

Restore callback reasons are correct, but persistence is unsupported. The property-string grammar, quaternion input, case-sensitive object-name lookup, one-shot scheduling policy and synchronous object-message delivery are explicit tested contracts that still need comparison with actual M2/M3 content and reference execution. `Key`'s world-only property reads and the original cooperative-mode option check are retained, not patched speculatively.

Windows/MSVC and macOS/Apple Clang runners are unavailable. Android, iOS and OpenXR sessions remain untested. Linux compiler coverage is GCC and Clang; do not generalize it to other ABIs or GPU backends.

M2 should begin with bounded REZ/world readers and the minimal original local-session path, adding the exact classes/services reached by the selected scenario. Extend these contract tests as those callers arrive. Review token-arena limits with actual message/object churn, and preserve explicit errors for services that are still missing. Do not expand the three-class M1 sample into a replacement gameplay system.

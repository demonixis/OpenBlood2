## Reproduce

From `Blood2/` on this configured machine:

```sh
cmake --preset local-debug
cmake --build --preset debug -j8
ctest --preset debug
./build/debug/blood2 --inspect-world
./build/debug/blood2
./build/debug/blood2 --start-game
```

The last command deliberately returns **6**, with `RunWorld blocked: 190 ...` after the continuation. This is a tested failure, not a launch instruction for a working game. Default graphical startup opens the world inspector. `--world NAME` selects a different resource but does not assert support for all its classes/format variants. `--check-data` remains the metadata-only mode; `--gpu-smoke` retains the synthetic M1 sample. `--world-smoke` uses the private world.

```sh
cmake --preset local-release
cmake --build --preset release -j8
ctest --preset release
cmake -S . -B build/sanitize -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ \
  -DBLOOD2_INSPECTOR=OFF -DBLOOD2_SANITIZERS=ON -DBLOOD2_GPU_TESTS=OFF \
  -DBLOOD2_TEST_DATA_DIR="/home/yann/.steam/steam/steamapps/common/Blood II/"
cmake --build build/sanitize -j6
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1 \
  ctest --test-dir build/sanitize -L headless --output-on-failure
```

Elsewhere use public `debug`/`release` presets. GPU/private tests are opt-in; omit `BLOOD2_TEST_DATA_DIR` for synthetic-only checks. `-L world` selects the new loader/session tests. Dependencies/drivers are not sanitizer-instrumented, and no GPU sanitizer run is claimed.

## Lighting clarification for later milestones (2026-10-15)

The project owner clarified that Blood II `DirLight` entries represent spotlights,
not the scene's main directional light. Treat this as guidance to verify against
the original preprocessor and retail lighting; the class name must not drive a
modern directional-light mapping. The main directional light is implicit in Blood
II. Determine how to recover it from the original pipeline and compiled world
data. Shogo has an explicit property to investigate as a comparison, but its
meaning and availability in Blood II must be established before reuse.

This does not change M2 source-entry accounting: original `CF_NORUNTIME` lights
remain preprocessor inputs, with their properties retained for inspection. It
does not yet establish a runtime lighting reconstruction algorithm.

The original `AppHeaders/engineobjects.c` DirLight registration contains
`LightRadius`, `InnerColor`, `OuterColor` and `FOV`, supporting the spotlight
interpretation. A separate `GlobalDirLight` SDK class exists, but none is present
in the selected SubwayA source entries; that alone does not determine a global
light for every level. The precise Shogo property and a reliable Blood II
recovery rule have not yet been identified.
